# Everything I Need From You

The complete list of content and images required to turn the placeholder site
into the real Sample Portfolio website.

**Read the first section before you start gathering anything.** It will save you
a large amount of work.

---

## Read this first: you do not need all of it

The site currently has **125 image slots** and about **4,000 words** of
placeholder text. That is what a mature practice with a 20-year archive fills.

You almost certainly should not try to fill all of it now. An architecture site
is judged on the quality of what it shows, not the quantity. **Six well-shot
projects with real descriptions beat twelve thin ones**, every time.

So there are two lists below.

### The launch minimum — what you actually need to go live

| Item | Quantity | Why this number |
|---|---|---|
| Projects | **4–6** | Below 4 the grid looks empty; above 6 you start padding |
| Photos per project | **6–10** | Fewer than 6 and the page has no rhythm |
| Home slideshow images | **3–5** | Your strongest single images, one per project |
| Principal portraits | **1 per principal** | Non-negotiable — people hire people |
| Team headshots | **0 or all** | A half-full grid looks worse than no grid |
| Firm description | **2–3 paragraphs** | The most-read text on the whole site |
| Design philosophy | **1–2 paragraphs** | |
| Per-project description | **2–4 paragraphs** | |
| News / awards / press | **0 or whatever is true** | Empty sections get deleted, not padded |
| Studio address, phone, emails | all | |

That is roughly **45–70 images** and **1,200 words**. Achievable in a week if the
photography exists.

### The full build — what the site can hold

Everything in the tables further down. Grow into it over the next year.

**If a section has nothing real to put in it, tell me and I will remove it
entirely.** A News page with two items looks unfinished. No News page looks
deliberate. This applies to News, Press, Awards, Books, and the Team grid.

## D · Projects — the main body of work

**Per project**, I need the following. There is a fill-in template at
`intake/03-projects.md` — one copy per project.

### Text

| # | Field | Notes |
|---|---|---|
| D1 | Project name | As you want it titled |
| D2 | Location | City, or city + state |
| D3 | Year completed | |
| D4 | Category | Must be one from A11 |
| D5 | Description | **2–4 paragraphs minimum.** The brief, the site, the response, the materials. This is what separates a portfolio from a photo album |
| D6 | Pull quote *(optional)* | One sentence lifted from D5, shown large mid-page |
| D7 | Built area | e.g. "640 sqm" — optional |
| D8 | Client | "Private" is fine |
| D9 | Project team | Names of who worked on it |
| D10 | Photographer credit | **Ask your photographer before publishing.** Most licences require attribution |
| D11 | Feature on homepage? | yes / no |

### Images

| # | Slot | Count | Notes |
|---|---|---|---|
| D12 | Cover | 1 | The grid thumbnail. Often not the same as the hero — it needs to read at small size |
| D13 | Hero | 1 | Full-width banner at the top of the project page. Landscape, and it will be cropped to 16:9 |
| D14 | Gallery | **6–12** | The main sequence. Order matters — see below |

**Ordering the gallery.** Name your files so they sort into the order you want
them shown: `01-approach.jpg`, `02-verandah.jpg`, `03-living.jpg`. A good
sequence usually reads like a walk through the building — arrival, exterior,
principal spaces, detail, then something quiet to end on.

**Captions** are optional. Use them for anything a photograph doesn't explain by
itself — a material, a technique, a name.

## E · News, Press, Awards, Books

**All four of these sections are optional.** Tell me which to delete.

| # | Section | I need per entry |
|---|---|---|
| E1 | News highlight | One sentence + a date + an image + a link (if any) |
| E2 | Press | Publication, article title, author, page range, date |
| E3 | Awards | Award name, category, project, and the year to group it under |
| E4 | Books | Book title, publisher, city, year |

**News** entries read as sentences, not headlines. For example:
*"Riverside House wins Best Residential Interior at the 2026 Trends Awards."*
Each one needs an image — usually the project it's about, or a photo of the
award/publication.

Press, Awards and Books need no images at all. They are text lists.

> If you have three awards, that's a real Awards page. If you have none yet,
> deleting the section costs you nothing and padding it costs you credibility.

## G · Photography specification

Give me the **largest files you have.** Don't resize, crop or compress anything —
the pipeline handles all of it, and every manual edit loses quality it can't
recover.

| Property | What I want |
|---|---|
| Size | The original. 10–15 MB is ideal, 50 MB is fine |
| Format | JPG, TIFF, PNG, HEIC, WebP — all handled |
| Resolution | Any. 300 DPI print files are converted to 72 DPI automatically |
| Colour | Any. CMYK print files are converted to RGB automatically |
| Orientation | Any. Camera rotation flags are applied automatically |
| Minimum width | **2400px for heroes, 2000px for gallery.** Anything smaller gets upscaled and will look soft |

**What I cannot fix:**
- An image that's too small to begin with
- A photograph that's out of focus or badly exposed
- A screenshot of a photograph
- An image pulled from Instagram or WhatsApp (already compressed and downsized)

Always go back to the photographer's original files.

## Suggested order of work

Do it in this sequence. Each step makes the site usable on its own, so you can
stop at any point and still have something coherent.

1. **Section A** — studio details. Half an hour, and it removes every fake phone
   number and email from the site.
2. **Section C1–C7** — the firm description and principals. This is the highest-
   value writing you will do.
3. **One complete project** — text and images. This proves the whole pipeline
   works end to end and gives you a template for the rest.
4. **Three to five more projects.**
5. **Section B** — the home page, chosen from the images you now have.
6. **Section E** — news and awards, only if there's something real.
7. **Section F** — logo and favicon.
8. **Section G/H** — photographer credits and permissions before you go live.

## What happens when something is missing

| Situation | What I'll do |
|---|---|
| Fewer projects than 12 | Delete the extra folders. The grid adapts |
| No photo for one slot | Leave the neutral grey placeholder. It reads as "coming soon", not as broken |
| No project description yet | Put one honest factual sentence in. Never lorem ipsum — that reads as an abandoned site |
| No team photos | Delete the whole Team section |
| No awards or press | Delete those pages and their nav tabs |
| No logo file | Keep the typographic logo. It suits this design language anyway |
| Photo too small | I'll flag it. You'll need a bigger original — this one I can't work around |

The governing principle: **ship less, complete.** Every visible placeholder costs
more credibility than the missing content would have earned.
